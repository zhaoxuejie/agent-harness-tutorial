CHAPTER 03 · 长出一个执行层

基础 Harness：把循环"托管"起来

前两章的循环还散在脚本里。这一章我们把"怎么跑循环、怎么管步数、怎么调工具"抽成一个执行层——这就是你的第一个 Harness。

01本阶段目标

学完你应该能

  • ✓理解 Harness 为什么是"循环的所有者"
  • ✓把 Agent（大脑）与 Harness（身体/执行）解耦
  • ✓给循环加上最大步数，堵住死循环

02原理：Harness = 循环的所有者

到目前为止，循环逻辑和业务逻辑混在一起。一旦你同时跑多个 Agent、要统一处理错误、要限制步数，散装的代码就会崩成一团。

Harness 的职责就是把"如何执行"从"执行什么"里拆出来：Agent 只负责思考和决策，Harness 负责驱动循环、调用模型、调度工具、强制退出的规则。它像一辆车的车架与线束，把各个部件固定并连接起来。

这一章开始，"Harness" 正式登场。它的英文原意正是"线束"——把分散部件捆在一起、让信号有序流动的那一层。

03最小可运行代码

harness.py · 阶段 03
# harness.py — 阶段 03：抽出执行层，循环归 Harness 所有
class Harness:
    """执行层：负责跑循环、调模型、调工具、限步数。"""

    def __init__(self, agent, tools=None, max_steps=10):
        self.agent = agent          # 大脑：只负责思考
        self.tools = tools or {}    # 工具注册表
        self.max_steps = max_steps  # 硬上限，堵死死循环
        self.history = []           # 观察区

    def execute_tool(self, name, args):
        if name not in self.tools:
            raise KeyError(f"未知工具: {name}")
        return self.tools[name](**args)

    def run(self, user_input: str) -> str:
        self.history.append({"role": "user", "content": user_input})
        step = 0
        while step < self.max_steps:          # 循环由 Harness 驱动
            step += 1
            out = self.agent.reason(self.history)   # ① 思考
            if out.get("tool_call"):                # ② 行动
                name, args = out["tool_call"]
                try:
                    result = self.execute_tool(name, args)
                except Exception as e:              # 观察：错误也回填
                    result = f"ERROR: {e}"
                self.history.append(
                    {"role": "tool", "name": name, "content": result})
                continue
            return out["text"]                      # ③ 输出
        return "已达最大步数，强制结束。"

# 大脑：只思考，不知道循环怎么跑
class Agent:
    def reason(self, messages):
        return {"text": "（模型回复）"}     # 或 {"tool_call": (name, args)}
  • 解耦：Agent 不再自己 while True，只暴露一个 reason()。
  • 托管：循环、工具、历史、步数全部收进 Harness。
  • 安全网：max_steps 让循环必然终止；异常被捕获回填成观察，Agent 得以继续而不是崩掉。
这一步是整个教程的"分水岭"：从此以后，你所有的架构（插件、记忆、状态、多 Agent）都挂在这个 Harness 上，而不是塞进 Agent 里。
