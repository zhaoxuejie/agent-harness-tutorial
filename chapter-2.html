CHAPTER 02 · 装上手脚

工具调用：让 Agent 长出 手和脚

只靠对话，Agent 永远是"嘴上王者"。这一章我们用一张注册表给循环注入真实能力——计算、查时间，任何你定义的函数。

01本阶段目标

学完你应该能

  • ✓理解"工具注册表"：名字 → 可调用函数
  • ✓看懂模型输出 tool_call 时，Agent 如何执行并回填结果
  • ✓明白"行动"从 print 升级为"调用外部世界"的那一刻发生了什么

02原理：Agent 是怎么"伸手"的

关键转变在模型的输出。上一章模型只能输出文本；这一章我们让模型在"直接回答"和"想调用工具"之间做选择——当它输出 tool_call 时，Agent 就去注册表里找到对应函数并执行。

工具的执行结果以 tool 消息 写回历史，作为"观察"回到思考。这保证了 Agent 能基于真实世界的反馈继续推理，而不是凭空瞎编。

"工具"的本质，就是把不可控的真实世界接入可控的循环。注册表是解耦的关键：新增一个能力，只要加一个函数，不改循环。
flowchart TD
    USER[用户输入] --> LLM[思考：模型判断]
    LLM --> CHOICE{输出类型}
    CHOICE -->|直接回答| ANS[Agent 输出文本]
    CHOICE -->|tool_call| LOOK[查注册表 TOOLS]
    LOOK --> RUN[执行工具 fn]
    RUN --> BACK[结果以 tool 消息写回]
    BACK --> LLM

03最小可运行代码

tools.py · 阶段 02
# tools.py — 阶段 02：给 Agent 装上工具注册表
TOOLS = {}                     # 注册表：名字 -> 可调用函数

def tool(name):
    """装饰器：把一个函数注册为 Agent 可用工具。"""
    def deco(fn):
        TOOLS[name] = fn
        return fn
    return deco

@tool("calculate")
def calculate(expr: str):
    return str(eval(expr))     # 简易计算器（生产环境勿用 eval）

@tool("current_time")
def current_time(_unused=""):
    from datetime import datetime
    return datetime.now().isoformat()

def llm_reason(messages):
    """占位：真实环境返回 {'text': ...} 或 {'tool_call': ('name', {args})}"""
    return {"text": "（模型回复）"}

def run(user_input: str):
    messages = [{"role": "user", "content": user_input}]
    while True:
        out = llm_reason(messages)               # ① 思考
        if out.get("tool_call"):                 # ② 决定行动
            name, args = out["tool_call"]
            result = TOOLS[name](**args)         # ③ 行动：执行工具
            messages.append({"role": "tool",     # ④ 观察：结果写回
                             "name": name, "content": result})
            print(f"[工具] {name}({args}) -> {result}")
            continue                             # 回到思考
        print("Agent >", out["text"])            # 直接回答，结束
        break

run("现在几点了？")
  • 注册表 TOOLS 用装饰器填满，新工具＝新增一个带 @tool 的函数。
  • tool_call 是模型表达的意图："我想调用 calculate(17*23)"。
  • 循环次数 此刻 ≈ 工具调用次数——每次调用都回到顶部再思考一次。
死循环风险：如果模型反复请求同一个工具，循环会停不下来。这就是为什么真实 Harness 必须限制最大步数——我们在阶段 03 会加。
