多 Agent：让 Harness 学会 调度

一个 Agent 干不了所有事。把任务拆分给"专才"Agent，由一个 Harness 当指挥官来编排——这是 Agent 系统走向复杂的必经之路。

01本阶段目标

学完你应该能

  • ✓理解"多 Agent"的两类形态：编排器 + 专才
  • ✓让 Harness 持有多个 Agent，并按需调度
  • ✓看懂"任务拆分 → 委派 → 汇总"的循环

02原理：编排器 + 专才

常见的多 Agent 形态是编排器（Orchestrator）+ 若干专才 Agent：指挥 Agent 拆解任务，把子任务分给写代码的、查资料的、做决策的专才；专才各跑各的 Harness 循环，再把结果汇总回来。

注意：每个专才仍然是一个独立的 Agent Loop（甚至可以复用我们前面造的 Harness）。多 Agent 不是新魔法，而是"多个循环 + 一个调度者"的组合。

调度者的职责：拆解（把大任务切碎）、委派（按能力分配）、汇聚（收集并整理结果）、决策（要不要继续派活）。

# multi.py — 阶段 07：编排器调度多个专才 Agent
class Harness:
    """复用前面的执行层：每个专才都有自己的循环。"""
    def __init__(self, agent, tools=None, max_steps=8):
        self.agent = agent
        self.tools = tools or {}
        self.max_steps = max_steps
        self.history = []

    def run(self, prompt):
        self.history.append({"role": "user", "content": prompt})
        step = 0
        while step < self.max_steps:
            step += 1
            out = self.agent.reason(self.history, self.tools)
            if out.get("tool_call"):
                name, args = out["tool_call"]
                result = self.tools[name](**args)
                self.history.append(
                    {"role": "tool", "name": name, "content": result})
                continue
            return out["text"]
        return "已达最大步数"

class Orchestrator:
    """调度者：持有并委派多个专才。"""
    def __init__(self):
        self.specialists = {}          # 角色名 -> Harness

    def add_specialist(self, role, harness):
        self.specialists[role] = harness

    def run(self, task):
        # ① 拆解：让调度模型决定派给谁
        plan = self._plan(task)        # 如 {"coder": "写一个排序函数"}
        results = {}
        # ② 委派：每个专才跑自己的循环
        for role, sub in plan.items():
            harness = self.specialists[role]
            results[role] = harness.run(sub)
        # ③ 汇聚：汇总成最终答案
        return self._synthesize(task, results)

    def _plan(self, task):
        return {"coder": task}         # 占位：真实由模型拆解

    def _synthesize(self, task, results):
        parts = [f"[{r}] {v}" for r, v in results.items()]
        return task + "\n\n" + "\n".join(parts)

# ---- 组装 ----
orch = Orchestrator()
orch.add_specialist("coder",   Harness(agent=CoderAgent()))
orch.add_specialist("researcher", Harness(agent=ResearcherAgent()))
print(orch.run("实现一个冒泡排序，并解释复杂度"))
  • 专才复用：每个专才仍是独立 Harness，前面所有能力（工具/记忆/状态）都能装。
  • 拆解：_plan 由调度模型决定"谁干什么"。
  • 委派 + 汇聚：run 分发子任务，再汇总各路结果。
多 Agent 最大的坑是失控与成本：Agent 越多，模型调用越多、越难追踪。下一章的观测面板，正是为驯服这种复杂性而生。
