02原理：可观测性 = 日志 + 追踪 + 指标

Agent 系统比普通后端更"黑"：每一步都在变，出了错不知道是模型抽风还是工具崩了。可观测性三件套：

  • 日志（Log）：离散的事件记录——"调用了 calculate，耗时 80ms"。
  • 追踪（Trace）：一次任务的完整执行链——编排器 → 专才 → 工具，串成树。
  • 指标（Metric）：聚合数字——平均步数、成功率、token 消耗。

我们前面造的 Step 记录 + 状态快照 已经给追踪打好了底。这一章把它变成一个可视化面板，你在下面就能"看到"一个 Agent 是怎么一步步解决问题的。

04工程化落地清单

教程到此为止是"讲清原理的最小实现"。真要上线，把这几件事补上：

从原型到生产的 Checklist

  • ✓接口化：把 Harness 封装成可复用类/服务，模型与工具都走接口
  • ✓持久化：状态/记忆存入数据库，支持跨会话恢复
  • ✓限流与配额：token、步数、并发都要有硬上限
  • ✓安全：工具白名单、参数校验、敏感信息脱敏（阶段 06 提到过）
  • ✓可观测：接入日志/追踪/指标，统一 trace_id
  • ✓重试与降级：模型超时重试、工具失败降级回填
